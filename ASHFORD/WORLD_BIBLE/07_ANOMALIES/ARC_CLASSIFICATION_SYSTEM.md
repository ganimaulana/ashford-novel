# ARC CLASSIFICATION SYSTEM

## Status

**Multi-axis classification framework** for ARC attributes, constraints, and negation.
**Last Updated:** 2026-08-31

---

## Core Principle

> **The danger of an ARC is not determined solely by what it can do, but by what happens when its rules are understood, manipulated, or combined with another ARC.**

Leon does not become powerful by owning the strongest ARC.
Leon becomes powerful by understanding that every ARC obeys a rule — and rules can be learned.

---

## 1. Multi-Axis Classification

ARC classification is NOT a power ranking (D/C/B/A/S).
Each ARC has **independent axes** — one ARC can be light but difficult to control, or very powerful but extremely limited.

Each ARC has minimum 6 attributes:

| Axis | Options | Description |
|------|---------|-------------|
| **Form** | Object, Entity, Location, Event, Phenomenon, Information, Ritual, Conceptual, Composite | What type of phenomenon |
| **Persistence** | Permanent, Temporary, Conditional | How long the ARC itself exists |
| **Use Type** | Reusable, Limited-use, Consumable | How it can be used |
| **Threat** | Harmless, Minor, Dangerous, Severe, Catastrophic | Potential for harm |
| **Control** | Stable, Conditional, Unstable, Uncontrollable | How predictable it is |
| **Temporal Constraint** | None, Time-limited, Periodic, Time-specific | Time-based restrictions |

### Examples

```
ARC-017
Form: Object
Persistence: Permanent
Use Type: Reusable
Threat: Minor
Control: Stable
Temporal Constraint: Once per day
```

```
ARC-004
Form: Phenomenon
Persistence: Permanent
Use Type: Conditional
Threat: Severe
Control: Unstable
Temporal Constraint: Active only during lunar eclipse
```

Both are ARC, but their nature is completely different.

## 2. Use Type Categories

### Consumable
ARC is destroyed after use.

**Example:**
- A paper that erases one name from a specific record.
- After use: paper turns to ash.

**Important:** Consumable ≠ weak.
Consumable can be extremely valuable.

### Limited-Use
Does not disappear immediately, but has a usage count.

**Example:**
- Can be used 7 times.
- After the 7th use: deactivated.

**Variation:**
- Each use reduces something (mass, size, quality).

### Reusable
Can be used repeatedly.

**But reusable ≠ unlimited:**
- Cooldown periods
- Conditions required
- Time restrictions
- Cost per use
- Physical deterioration
- Compatibility requirements
- User requirements

## 3. Temporal Constraints

Time limits make ARC a puzzle, not a superpower.

| Constraint | Description | Example |
|------------|-------------|---------|
| **Cooldown** | Minimum time between uses | Once per day |
| **Duration** | How long effect lasts | 13 minutes |
| **Window** | Only usable during specific time | 00:00–00:13 |
| **Cycle** | Active on a repeating schedule | Every 7 days |
| **Environmental Time** | Depends on natural conditions | Only at sunset |
| **Historical Condition** | Only on specific dates | Only on December 21 |
| **Triggered Duration** | Lasts until condition met | Until someone speaks a name |

## 4. Activation Conditions

ARC may require specific conditions to activate.

| Category | Description | Example |
|----------|-------------|---------|
| **Physical** | Touch or physical contact | Must be touched |
| **Environmental** | Specific location or setting | Must be in a specific room |
| **Temporal** | Specific time | Only at midnight |
| **Behavioral** | User must perform an action | User must lie |
| **Mental** | User must know something | User must know a specific name |
| **Emotional** | User must feel something | Only when afraid |
| **Informational** | Requires specific knowledge | User must know a secret |
| **Relational** | Depends on relationship | Only works on someone who trusts the user |
| **Symbolic** | Requires specific symbols | Must draw a specific sigil |
| **Composite** | Multiple conditions simultaneously | Required for high-level ARC |

**Composite conditions** are ideal for high-level ARC.

## 5. Negation System

Leon is NOT immune to ARC.
Leon understands how ARC works — and disrupts the conditions that make ARC active.

### Level 1 — Avoidance
Leon avoids activation conditions.

**Example:**
- ARC activates if someone speaks a name.
- Leon: does not speak the name.

### Level 2 — Interruption
Leon stops the process before completion.

**Example:**
- ARC requires 10 seconds to activate.
- Leon disrupts at second 7.

### Level 3 — Suppression
Leon uses another ARC to suppress the first.

**Example:**
- ARC-A produces effect X.
- ARC-B: blocks conditions required by ARC-A.

### Level 4 — Cancellation
ARC-B directly cancels ARC-A's effect.

**Warning:** This must be rare.
If too many ARC can cancel each other, the system becomes too easy.

### Level 5 — Reversal
The most interesting level.

Leon does not stop ARC.
He makes ARC work against its source.

**Example:**
- ARC-A: the more people see it, the stronger it becomes.
- Leon uses ARC-B: transforms "seeing" into "not realizing one saw."
- ARC-A remains active.
- But its condition is no longer met in the expected way.

---

## 6. Counter System

ARC can counter other ARC — but not always 1:1.

### Direct Counter
ARC-A is specifically countered by ARC-B.

**Example:**
- ARC-A: Makes someone unable to lie.
- ARC-B: Erases understanding of specific words.

ARC-B appears useless individually.
Against ARC-A: ARC-B becomes a counter.

Because ARC-A requires the concept of "lie" to function.

### Synergistic Counter
ARC-A + specific condition + ARC-B = negation.

**Example:**
```
ARC-A: activates when someone sees an object.
ARC-B: alters visual perception.

ARC-B alone: not dangerous.
ARC-A + ARC-B: ARC-A fails to recognize the object is being seen.
```

The question is not: "Which ARC is stronger?"
The question is: "Which ARC understands the rule of the other ARC?"

## 7. Power vs Utility

An ARC can have:

| Dimension | Description | Question |
|-----------|-------------|----------|
| **Raw Power** | Magnitude of supernatural effect | How big is the effect? |
| **Utility** | Number of situations it can help | How many uses? |
| **Precision** | How exact is the effect? | Can it be targeted? |
| **Reliability** | How consistent is the effect? | Does it work every time? |
| **Synergy** | How well does it combine? | Does it enable combinations? |
| **Counter Potential** | How well does it counter other ARC? | Can it negate? |

**Formula:**

```
Weak ARC + High Synergy + High Precision
can be far more valuable to Leon than
Powerful ARC + Low Control
```

## 9. Leon's ARC Analysis Method

Leon's progression:

```
Stage 1: "How do I use this ARC?"
Stage 2: "How does this ARC work?"
Stage 3: "Why does it work that way?"
Stage 4: "What can this ARC NOT do?"
Stage 5: "What happens if I force it to interact with another ARC?"
```

At Stage 5, Leon begins to become dangerous.

### Analysis Questions

For each ARC, Leon tests:

1. What triggers it?
2. What changes?
3. What is exchanged?
4. What moves?
5. What is replaced?
6. What accumulates?
7. What happens at the threshold?
8. Does the effect repeat itself?
9. Does the effect strengthen itself?
10. Is the apparent effect actually the opposite of the real mechanism?

### The Critical Question

> **"What assumption am I making that the ARC itself never actually confirmed?"**

In a mystery system like Ashford, the greatest mistake is not failing to know a fact — it is **mistaking interpretation for fact**.

## 12. Design Principles

### For ARC Classification
1. One ARC can be light but difficult to control
2. One ARC can be powerful but extremely limited
3. Classification is NOT a power ranking
4. Multiple axes create variety without hierarchy

### For Negation
1. Avoidance > Interruption > Suppression > Cancellation > Reversal
2. Cancellation must be rare
3. Reversal is the most interesting
4. Leon's understanding > any anti-ARC power

### For Counters
1. Counters are not always 1:1
2. Counters can be synergistic combinations
3. "Useless" ARC can counter powerful ARC
4. Understanding rules > raw power

### For Leon
1. Leon is NOT immune to ARC
2. Leon's advantage is understanding
3. Leon's collection appears trash but is strategic
4. Leon's growth: use → understand → question → combine
5. Leon's principle: "An ARC does not need to be powerful. It only needs to obey a rule."

### For Ashford
1. ARC danger = what happens when rules are understood
2. The greatest mystery is not what ARC does, but why it obeys its rules
3. The greatest danger is not raw power, but understanding
